# README media

[← Main README](../../README.md)

The main README includes explicit media placeholders so that its layout works before screenshots or a recording are available. They are illustrations of available space, not captures of the application.

## Screen recording

Replace the recording placeholder with a 30–60 second walkthrough:

1. Open the guided example or a small public demonstration project.
2. Inspect a block and its declared power or signal interface.
3. Make a connection or change a load and show the related finding.
4. Open Power Review and finish with an exported Design Review.

Capture at 1280×720 or higher, keep text readable, and exclude private file paths and design data. Upload the MP4 to a GitHub issue or pull-request attachment and paste its resulting video URL into the README's recording position. Alternatively, link a hosted recording from a real preview image. GitHub's rendered README can show supported uploaded video links.

Remove the placeholder caption when the actual recording is present. Do not commit a large video binary solely to provide a README preview.

## Screenshots

Replace the two screenshot placeholders with real captures of:

- **Canvas:** a named design with functional blocks, an upstream supply, a converter, and several connected interfaces.
- **Review:** Design checks or Power Review with readable verdicts and useful context. A Requirements view is another useful addition.

Save reasonably compressed PNG or WebP files in this directory, update the README image paths and alt text, and remove the placeholder caption once all media is real. Crop unnecessary desktop chrome and use a consistent window size. Retain clear labels and enough detail to understand what the app is showing.

Existing placeholder files can be deleted after the README no longer references them.
